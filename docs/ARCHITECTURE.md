# Architecture — GCP2 Experiment Console v0.4.2

## Execution model

The extension uses Chrome Manifest V3.

`background.js` registers a `chrome.action.onClicked` handler. When the user clicks the extension icon, Chrome injects `main.js` into the active tab:

```js
chrome.scripting.executeScript({
  target: { tabId: tab.id },
  files: ["main.js"],
  world: "MAIN"
});
```

The **MAIN** world is required because the collector may need access to the GCP2 page's `window.geoACData` fallback.

## Origin restriction

`main.js` immediately checks that the active page hostname is `gcp2.net` or a subdomain. Otherwise it aborts.

The manifest host permission is:

```text
https://gcp2.net/*
```

## Live API client

The client reads the GCP2 site's API bearer token from:

```text
/js/data/api_token.js
```

It calls:

```text
/api/getgeogroupac
/api/getcurrentnetvar
```

Requests use:

- `GET`
- `cache: no-store`
- `credentials: same-origin`
- `Authorization: <Bearer token>`

If a request returns HTTP 401 or 403, the token is discarded, re-read once, and the request is retried.

## Fallback behavior

If the direct device endpoint fails, the code attempts to use:

```js
window.geoACData
```

from the GCP2 page as the device-data fallback. It separately attempts the network-variance endpoint.

The status area records whether the capture used the direct API or the page live-map fallback.

## Polling

```text
POLL_MS = 35000
STALE_MS = 90000
GAP_MS = 90000
```

Every scheduled poll attempts to capture one sample for the currently selected node.

The UI's LIVE / STALE indicator is driven by the age of the last successful local capture, not by whether the numeric value changed.

## Node discovery

Each GeoJSON feature is normalized into:

- node ID;
- node label;
- coordinates;
- properties;
- Device Coherence `ac`;
- GCP2 fill color.

The node selector is populated from the current set of live features.

## Coherence classification

The source GCP2 fill color is compared with the reference palette:

```text
Normal     226,0,226
Elevated   0,206,247
High       247,197,58
Very High  255,255,0
Extreme    255,255,222
```

The nearest RGB reference determines the stored `device_level`.

For the visual indicator, the exact parsed source color is preferred when available.

## Storage

The browser database remains:

```text
ContactProject_GCP2_58114
```

for backward compatibility.

Object stores:

```text
samples — keyPath: captured_at
markers — keyPath: timestamp
```

The multi-node implementation filters records by `node_id`.

Per-node notepad text and the selected node are stored with `localStorage`.

## Charting

The chart is an inline SVG generated by `main.js`.

Node AC and Network Variance use separate Y scales.

Time windows:

```text
1h
6h
24h
all
```

Samples separated by more than `GAP_MS` are split into independent polyline segments.

Markers are plotted by timestamp only when they fall inside the currently displayed interval.

## Compatibility

The `normalizeAc()` helper accepts several historical record layouts:

```text
row.ac
row.numeric_properties.ac
row.properties.ac
row.raw_feature.properties.ac
```

The significance level is similarly reconstructed from historical fill-color locations when necessary.

This allows older data already present in IndexedDB to remain usable after extension updates.

## Backup model

Database backup is application-level JSON rather than a direct copy of Chrome's internal LevelDB files.

That makes backups portable across Chrome installations and easier to inspect, version, archive, and restore.
